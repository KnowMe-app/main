# Анкети з групового чату Telegram

Мета — не читати вручну сотні повідомлень, а дати Claude пройти чат, відсіяти
світські розмови й скласти по кожній людині те, що стосується програми та
анкети. Чат захищений (копіювання, пересилання, експорт і знімки екрана
вимкнені), тож єдиний шлях до тексту — Claude дивиться на екран Telegram
Desktop і гортає сам.

Робота ділиться на дві фази, і це навмисно:

1. **Читання** — у застосунку Claude на вашому компʼютері (керування
   компʼютером). Результат — один файл `telegram_intake.json`.
2. **Запис у KnowMe** — у хмарній сесії Claude Code на цьому репозиторії.
   Там є код застосунку й доступ до бази, і картки лягають так само, як із
   форми «Створити картку».

Змішувати фази не варто: читання екрана — довге й ламке, і файл посередині
дає змогу перевірити все до того, як щось потрапить у базу.

## 0. Перевірка, чи взагалі вийде (5 хвилин)

Керування компʼютером працює через знімки екрана, які Claude робить сам. Якщо
Telegram для захищеного чату ховає вікно від захоплення екрана, Claude побачить
там чорний прямокутник — так само, як ваш скриншот.

1. Відкрийте застосунок Claude на компʼютері (macOS або Windows) і нову
   розмову з увімкненим керуванням компʼютером.
2. Відкрийте Telegram Desktop на потрібному чаті.
3. Напишіть: «Зроби знімок екрана й перепиши дослівно три останні
   повідомлення з відкритого чату Telegram».

Якщо Claude переписав текст — продовжуйте. Якщо бачить чорне вікно, далі цей
шлях не веде; лишається скрипт `tg_export_with_usernames.py` (Telethon, читає
через API) або домовленість з адміністратором групи.

## 1. Підготовка до читання

- Компʼютер на час роботи не чіпати: Claude керує мишею й клавіатурою.
  Вимкніть сповіщення й заставку екрана.
- Telegram Desktop — на весь екран, шрифт стандартний, нічна тема вимкнена
  (світлий фон читається надійніше).
- Прогорніть чат до **дати, з якої треба почати**, або скажіть Claude цю дату:
  він знайде її сам через пошук за датою (значок календаря в пошуку чату).
- Дайте Claude дозвіл на Telegram, коли застосунок спитає.

## 2. Промпт для фази читання

Вставте в розмову з керуванням компʼютером цілком, підставивши дату й назву:

```
Ти читаєш груповий чат Telegram «<НАЗВА ЧАТУ>» у Telegram Desktop, починаючи
з <ДД.ММ.РРРР> і до найновішого повідомлення. Копіювати текст не можна —
читай лише зі знімків екрана. Нічого в чаті не пиши, не став реакцій, нікому
не відповідай і не відкривай посилань.

Порядок роботи:
1. Читай екран зверху вниз. Кожне повідомлення віднеси до однієї категорії:
   A — намір участі: людина хоче в програму донорства ооцитів чи
       сурогатного материнства, шукає агенцію/клініку/програму, питає умови,
       оплату, вимоги, каже, що вже в програмі чи була;
   B — анкетні дані про САМУ авторку: вік чи рік народження, область, місто,
       кількість пологів, дата останніх пологів, кесарів розтин (скільки),
       діти, зріст, вага, група крові, сімейний стан, досвід донацій чи
       сурогатного материнства, здоровʼя, курить чи ні;
   C — усе інше (світські розмови, побут, жарти, стікери) — пропусти.
   Факт про іншу людину («у сестри два кесарева») — не B для авторки.
2. Для кожної нової авторки з A чи B один раз клацни на її імʼя чи аватар,
   прочитай у профілі @username (і телефон, якщо видно), закрий профіль.
   Якщо ніка немає — запиши "".
3. Відносні дати переводь у точні від дати повідомлення («народила 3 міс
   тому» в повідомленні від 10.06.2026 → lastDelivery 2026-03, approx:true).
4. Гортай вниз приблизно на висоту екрана, щоб останнє прочитане
   повідомлення лишалось угорі як орієнтир. Не пропускай повідомлень.
5. Кожні 20 екранів дописуй результат у файл
   ~/Documents/telegram_intake.json (формат нижче) і записуй у поле
   "resumeFrom" дату й час останнього прочитаного повідомлення. Якщо роботу
   перервуть, продовжиш саме звідти.
6. Наприкінці коротко скажи: скільки людей, у скількох A, у скількох лише B,
   які повідомлення не вдалося прочитати.

Формат файлу:
{
  "chat": "<НАЗВА ЧАТУ>",
  "resumeFrom": "2026-06-10T14:32",
  "people": [
    {
      "displayName": "Оля Ковальчук",
      "username": "olya_k",
      "phone": "",
      "intent": "ed" | "sm" | "unknown" | null,
      "facts": {
        "birth": "1996", "region": "Київська", "city": "Бровари",
        "ownKids": "2", "lastDelivery": "2026-03", "csection": "2",
        "height": "", "weight": "", "blood": "", "maritalStatus": "",
        "experience": "", "smoking": ""
      },
      "evidence": [
        { "date": "2026-06-10", "category": "B", "field": "csection",
          "quote": "в мене два кесарева", "approx": false }
      ]
    }
  ]
}

Правила для facts: лише те, що авторка сказала про себе; порожнє — "";
нічого не домислюй. Якщо вона сказала по-різному в різний час — бери новіше,
а обидві цитати лиши в evidence. intent: "ed" — донорство ооцитів, "sm" —
сурогатне материнство, "unknown" — хоче в програму, але не сказала яку,
null — наміру не висловлювала (лише анкетні дані).
```

## 3. Фаза запису — хмарна сесія Claude Code

Відкрийте сесію на репозиторії `knowme-app/main`, прикріпіть
`telegram_intake.json` і напишіть: «Заведи анкети з telegram_intake.json за
docs/telegram-chat-intake.md».

Що робить сесія:

1. **Перевіряє файл**: формат, дати (`lastDelivery`, `birth` → `РРРР-ММ-ДД`,
   як їх пише форма), значення довідників (`csection`: `-` / `1` / `2`; роль
   з `intent`: `ed` / `sm`).
2. **Шукає кожну людину за ніком** — ключ `searchId/{нік}/telegram`
   (`buildSearchIdValueKey('telegram', нік)`), а без ніка — за телефоном.
3. **Показує таблицю на перевірку**: людина → поля → цитати → «знайдено
   (id) / нова картка». Нічого не пише, доки людина не скаже «так».
4. **Пише**:
   - знайдена картка — доповненням (`saveOverlayForUserCard`): адмін бачить
     його в черзі «Доповнення» і приймає по значенню, канонічна анкета сама
     не міняється;
   - не знайдена — нова картка-чернетка (`saveCreateProfileMutation`, той
     самий шлях, що й форма): роль, `telegram`, факти; у стрічці її немає,
     пошук знаходить;
   - цитати-докази — у приватну нотатку власника до картки
     (`multiData/comments/{owner}/{card}`), щоб було видно, звідки кожне
     значення.
5. **Звіт**: скільки заведено, скільки доповнено, що відлетіло з якою
   причиною.

Технічна примітка для сесії: код застосунку запускається з Node через jest
(`/** @jest-environment node */`, `--forceExit`, `NODE_USE_ENV_PROXY=1`),
вхід — `MIGRATION_EMAIL` / `MIGRATION_PASSWORD` з оточення. Тимчасовий скрипт
кладеться в `src/`, бо лише там працюють шляхи `components/…`, `utils/…`, і
**не комітиться**. Значень змінних оточення не друкувати.

## 4. Повторні проходи

Наступного разу дайте Claude `resumeFrom` з попереднього файлу як дату
початку. У фазі запису вже заведені картки знаходяться за ніком, тож нове
лягає доповненням, а не дублем.

## Обмеження, про які варто знати

- Читання екрана повільне: кілька секунд на екран, сотні екранів — це години.
  Запускайте на ніч, файл зберігається частинами.
- Розпізнавання не ідеальне: таблиця фази 3 існує саме для того, щоб людина
  переглянула кожне значення до запису.
- Чат захищений адміністратором навмисно, а дані — медичні й особисті.
  Варто домовитись з адміністратором групи; картки, заведені з чату,
  знаходить пошуком кожен авторизований користувач.
